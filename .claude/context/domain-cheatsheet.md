## 2. State machines
- **Approval case:** `PENDING` —SUBMIT→ `IN_REVIEW` —APPROVE→ `APPROVED` | —RETURN/REQUEST_INFORMATION→ `RETURNED` (—SUBMIT→ `IN_REVIEW`) | —REJECT→ `REJECTED`. Reason required on RETURN/REJECT. One decision row per action.
- **Node activation:** `INACTIVE` → `ELIGIBLE` (all gating predecessors COMPLETED/N-A; task/approval_case spawned) → `ACTIVE` (submitted/started) → `COMPLETED`. Side: `BLOCKED` (open BLOCKS issue), `NOT_APPLICABLE`/`SKIPPED`. INDETERMINATE-condition nodes stay `INACTIVE` with `blocking_reason {type:'CONDITION_UNKNOWN', fact}`.
- **Gating deps** = `BLOCKING`, `REQUIRES_COMPLETION` (state ACTIVE). `INFORMATIONAL`/`PARALLEL` never block. Deps touching N/A nodes → `DISABLED`. `CONDITIONAL` edges stay non-gating while their source node is `CONDITIONAL_PENDING`, become `BLOCKING` once it applies (original type kept in `condition.original_type`). Process order is NOT downgraded for advisory-rule nodes; instead each node carries `gateKind` (RULE_BACKED | CONFIGURED | ADVISORY | CONDITIONAL_PENDING | NOT_APPLICABLE) computed from its rule's executability, and only RULE_BACKED is ever called a "mandatory gate".

## 3. Rule executability & engine outcomes
Executable ⇔ `ENFORCEABLE ∧ VERIFIED ∧ effective_from ≤ today ≤ effective_to`. Outcomes: `ALLOWED | BLOCKED_BY_VERIFIED_RULE | REQUIRES_HUMAN_REVIEW | AUTHORITY_UNRESOLVED | RULE_NOT_CONFIGURED | RULE_CONFLICT | SOURCE_OUTDATED_OR_UNKNOWN`. Rule DSL: `{all:[..]|any:[..]|not:{..}|{fact,op,value}}`, ops `eq neq gt gte lt lte in exists`; missing fact ⇒ INDETERMINATE.
UI trust badges: `Verified source · Conditional · Contract-specific · Not verified · Superseded` + amber `SYNTHETIC DEMO` when `rule_versions.scope.synthetic=true` (or source `SRC-DEMO-SYNTHETIC`).

## 4. Authority resolver (never guess)
1 candidates = ACTIVE authority_rules ∧ dept/type/cost-band/date match ∧ **rule_version executable** → 0 ⇒ `NO_RULE`→`MANUAL_REVIEW`. 2 max specificity (count of non-null dept/type/jurisdiction_type/cost/conditions), then min priority; tie ⇒ `AMBIGUOUS`. 3 office by `routing_scope` (`OWNING_OFFICE`=project.owning_office_id; `PROJECT_JURISDICTION`=office covering project jurisdiction, walking parents). 4 holder from `v_current_position_holders` (PRIMARY first); none ⇒ `INACTIVE_POSITION`→`MANUAL_REVIEW`. 5 persist `authority_resolutions` + snapshot. Cost bands inclusive both ends ⇒ upper band `min = max + 0.01`.

## 8b. Engine facts learned while building (implemented + tested)
- `recompute(tx,ctx,projectId)` is THE propagation function (idempotent): activates ready nodes, spawns tasks/approval cases, auto-completes GATEs, raises `CONDITION_VERIFICATION` tasks, syncs `lifecycle_stage`/`operational_status`. Always `lockProject` first (lock order: project -> case/node).
- Task types: `WORK_ITEM` (complete via `POST /tasks/:id/complete`), `APPROVAL_SUBMIT`, `APPROVAL_DECISION`, `MILESTONE_UPDATE`, `CONDITION_VERIFICATION`, `MANUAL_AUTHORITY_REVIEW`. Tasks on VACANT seats are shown to `workflow.manage` users.
- Authority routing walks offices nearest-first and NEVER skips a vacant nearer seat. `SITE_HANDOVER` completion sets site possession via template `config.on_complete`.
- Events: ProjectCreated, ProjectSubmitted, WorkflowGenerated, TaskAssigned, ApprovalCaseOpened, AuthorityUnresolved, ApprovalSubmitted, ApprovalDecided, AuthorityManuallyAssigned, TaskCompleted, TaskOverdue, DocumentUploaded/Verified/Rejected. Dispatcher (`notifications.service.dispatchPending`) fans them out; ticker `tasks.jobs.tickOverdue` marks OVERDUE.
- Blocker analysis = frontier nodes with incomplete gating successors; flagged only if ISSUE_BLOCKS / APPROVAL_REJECTED / SLA_OVERDUE. Copy: "Current root blocker candidate: X. It is preventing N downstream steps from becoming ready."
- Test infra: `SKIP_DB_RESET=1 TEST_LOG=error npx vitest run <file>`; DB reset uses a fingerprinted template DB (~12s). No `.env` write access (deny rule) — config falls back to `.env.example`.
